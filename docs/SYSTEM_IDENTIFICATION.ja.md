# システム同定

飛行ログから[プラントモデル](PLANT_MODEL.ja.md)へ、そしてその逆へ。シミュレータの推定器は、ロータのアクチュエーション、抗力、電池を飛行に当てはめ、必要なら残りにデータで当てはめた補正を足します。**k ステップ予測誤差**は、シミュレータ（それらのパラメータあり・なし）が、当てはめに使っていない飛行をどれだけ再現するかを測ります。同じコードが、真のプラントが分かっているシミュレータの飛行（推定器がそれを取り戻せるかをテストで確かめる）にも、実機の飛行にも使えます。

```text
実機の飛行 (.ulg) ── convert-ulog ──┐
                                    ├─► 飛行ログ (.npz) ── identify ──► plant セクション（＋補正）
シミュレータ ── excite ─────────────┘                  └── predict ◄── そのプラントのシミュレータ
```

## 飛行ログ

`wheeled_uav.flightlog.FlightLog`: 1 つの時間軸、名前つきのチャンネル、メタデータ。`.npz`（`wheeled_uav.flightlog/1`）に保存します。ワールドは z 上向き（PX4 のログは NWU）、機体は FLU、四元数は `[w, x, y, z]` で機体からワールドへ。チャンネル:

| チャンネル | 幅 | 中身 |
| --- | --- | --- |
| `position`、`quaternion` | 3、4 | 必須 |
| `velocity` | 3 | ワールド速度（無ければ位置を微分） |
| `angular_velocity_body` | 3 | 機体の角速度 |
| `rotor_thrust_command` | 4 | ロータごとの推力の指令 [N]、`actuation.rotors` の順。アクチュエーションに必要 |
| `rotor_command` | 4 | 推力曲線が無いときの、正規化したモータ指令 |
| `rotor_speed` | 4 | 測ったロータの回転数 [rad/s] |
| `battery_voltage`、`battery_current` | 1、1 | 電池に必要 |
| `specific_force_body` | 3 | 加速度計（無ければ速度から） |
| `valid` | 1 | 元のデータの欠測の中は 0（当てはめから除く） |

指令はサンプルの間で保持し、測定値は線形に補間します。保持は、どのサンプルも指令の更新であるときに正確です。指令の更新の一部しか残していないログ（制御より遅い記録）は、メタデータに `"commands": "sampled"` と書き、指令も補間します。

**PX4 から。** `convert-ulog flight.ulg --out flight.npz [--mapping mapping.json]`（pyulog は `uv sync --extra logs`）。各チャンネルは、そのトピック自身の時刻から補間します（別のトピックの最も近いサンプルに合わせるのではありません）。トピックの抜け（中央値の周期の 3 倍より長い間）に入るサンプルは無効にします。時刻の基準は、ログにあればモータ指令のトピックです（対応の `time_base` で別のトピックか周波数にできます）。指令は、それを記録したサンプルから保持するので、指令が変わる時刻そのものをサンプルにするためです。測定値は、トピックに `timestamp_sample` があればその時刻に、指令は `timestamp` に置きます。既定の対応は `vehicle_local_position`、`vehicle_attitude`、`vehicle_angular_velocity`、`vehicle_acceleration`、`actuator_motors`、`esc_status`、`battery_status` を読みます。対応のファイルで、トピックとフィールド、`motor_order`（シミュレータの各ロータに当たるログのモータ）、`thrust_curve`（`T = Σ c[i][j] u^i V^j`。たとえば推力台での較正の、指令と電圧の 2 次元多項式）を上書きできます。推力曲線があればモータの指令を `rotor_thrust_command` に直します。無ければ同定できるのは抗力（と電池）だけです。

**シミュレータから。** `excite --out flight.npz [--plant plant.json] [--duration 20] [--measured]` は離陸して、リサジューの目標点（約 1 m/s。抗力のため）を追い、40〜160 ms ごとに符号の変わるランダムな推力の総和の揺さぶり（むだ時間とロータの時定数のため）と、小さな差動の揺さぶり（姿勢）を加えます。実機の励起飛行のひな形にもなります: 推定器に要るのはこういう動きです。

## 推定器

`identify flight.npz [--params-file ...] [--correction knn|linear] --out result.json` は、ログで可能なものを当てはめ、残差つきの結果と、それが示す `plant` セクションを書き出します（`--start`・`--end` で区間を選びます。壁や地面に触れていない飛行中の区間だけを使ってください）。

| 当てはめ | モデル | 要るもの |
| --- | --- | --- |
| アクチュエーション | `m f_bz = s Σ lag(delay(T_cmd)) − d_z v_bz + b`。プラントモデルと同じ `sqrt(T)` でのロータの遅れ（上げ・下げで別の時定数）。むだ時間と時定数は格子で探し、残りは最小二乗 | `rotor_thrust_command` |
| 抗力 | 機体の x・y ごとに `m f_b = F_thrust,b − D v_b (− q \|v_b\| v_b) + b`。非負の最小二乗 | 速度 |
| 電池 | `V = V_oc0 − R I − k Q` と `V I = c Σ T^1.5 + P_aux` | 電圧、電流 |
| 補正 | 上の当てはめで残った力の、k 近傍かリッジ回帰 | アクチュエーション |

`m` は params の機体の質量です（質量の誤差は、プラントの推力の倍率が吸収します）。`f_b` は加速度計の比力か速度の微分で、モデルも同じように平均します（中心差分は ±1 サンプルの間の力を平均するので）。指令が変わる時刻がログのサンプルに入っていれば、これでタイミングに偏りが出ません。制御より遅いログや、制御の更新の間で取ったログでは、指令の変化が最大 1 サンプル遅れて記録され、指令を保持して読むと、むだ時間が半サンプルかそれ以上短く出ます（1 kHz の制御に対して、250 Hz の記録で 2 ms、100 Hz で 5 ms）。そういうログは、変換の対応で `"commands": "sampled"` を指定します。指令を補間して読むので、むだ時間を取り戻せます。無効なサンプルの隣のサンプルも除きます（微分がそれを使うため）。params の推力の軸を使うので、ロータの傾きは推力の倍率に入りません。電流を測っていない、または電流がほとんど変わらないログでは、電池を飛ばしてその旨を notes に書きます。

シミュレータの飛行では、推定器はむだ時間（物理ステップの精度）、上げ・下げの時定数（1〜3 %）、推力の倍率（0.3 %）、抗力（3 %）、電池の抵抗と電力の係数（1〜3 %）を取り戻します（`tests/test_sysid.py`）。

## k ステップ予測誤差

`predict flight.npz --plant result.json --horizons 0.05 0.1 0.2 0.5` は、`--stride` 秒ごとに記録された状態からシミュレータを始め、記録されたロータの指令をそのまま与え（コントローラはループに入れません）、各ホライズンの後の位置・速度・姿勢の誤差（平均、中央値、90 パーセンタイル、最大）を報告します。各開始の前に、プラントのロータのモデルに直前 0.3 s の指令を通します。プラントモデルどうしは、当てはめに**使っていない**飛行で比べてください。真のプラントが分かっているシミュレータの飛行では、同定したプラントは 0.5 s 先を 2 mm 以内で予測し、プラントなしの剛体のモデルは 6〜8 cm ずれます。

## 実機で取るとよい飛行

1. 機体の重さを量り、慣性（2 本吊りの振り子）を測る。推定器は質量を既知とします。
2. モーションキャプチャの範囲で、ホバリングと励起飛行: 推力の総和のステップと擬似ランダムな揺さぶり（アクチュエーション）、実験と同じ速さまでの目標点の掃引（抗力）、いくつかの電池の残量で（電池）。
3. 全レートで記録: `vehicle_acceleration`、`vehicle_angular_velocity`、`actuator_motors`、`battery_status`、あれば回転数テレメトリ（双方向 DShot）つきの `esc_status`。
4. いくつかの飛行で同定し、別の飛行で予測誤差を確かめ、両方を報告する。
